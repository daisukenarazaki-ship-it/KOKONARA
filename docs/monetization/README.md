# 収益化プロジェクト 運用ガイド

目標: 月100万円（最終）/ まず初受注→月5万円（〜2026年9月）
戦略: AIコンテンツ制作の受注販売（SEO記事作成代行 + 店舗LP/HP制作）

## このディレクトリの構成

| ファイル | 内容 |
|---|---|
| STEP1-genre.md | ジャンル選定と業務分解表（入力・処理・出力・人間の判断） |
| STEP2-schedule.md | フェーズ計画・毎日のルーティン・KPI |
| STEP3-skill-selection.md | Skill化した業務／しなかった業務と理由 |
| STEP4-model-adjustment.md | 普段使いモデル向け調整の記録 |
| STEP5-qa.md | QA結果と人間が確認すべき箇所 |
| profile.md | 実績・受注ポリシーのマスター（**受注のたび更新**） |
| log.md | 日次の活動ログ（毎日1行） |

## Skill一覧（`.claude/skills/` 配下）

| Skill | 用途 | 呼び出しタイミング |
|---|---|---|
| proposal-writer | 公開依頼への提案文作成 | 毎日の提案タイム |
| seo-article | SEO記事の構成→執筆→検品 | 記事案件の受注中 |
| shop-lp | 店舗LP/HP制作（RE:BIRTH雛形） | サイト案件・ポートフォリオ制作 |
| daily-ops | 今日のTODO采配と記録 | 毎日の最初と最後 |

## 呼び出し方

**Claude Code（Opus 4.8等・このリポジトリで起動）:**
リポジトリを開けばSkillは自動認識される。
- `今日のタスクを教えて` → daily-ops が発動
- `この依頼に提案文を書いて: （依頼文コピペ）` → proposal-writer
- 明示的に呼ぶなら `/proposal-writer` のようにスラッシュで指定

**claude.ai / デスクトップアプリ（チャット）で使う場合:**
該当する `SKILL.md` の本文（---の下から）を会話の最初に貼り付けて、「このSkillに従って」と依頼する。プロジェクト機能があるなら、4つのSKILL.mdとprofile.mdをプロジェクトナレッジに登録しておくと毎回貼らずに済む。

## 安全原則（全Skill共通）

1. **送信・納品・公開・課金は必ず人間が行う。** AIの出力は常に下書き。
2. `【要確認】` `【要記入】` は創作防止の正常動作。埋めるのは人間。
3. 案件ファイルは `projects/` 配下。雛形（リポジトリ直下）は編集しない。
4. クライアント情報を他案件・SNSに転用しない。実績公開はクライアント許可を得てから。
